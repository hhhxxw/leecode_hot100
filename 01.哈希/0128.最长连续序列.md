## 题意与示例

在未排序的数组中，寻找数值依次相差 `1` 的最长序列，返回其长度。数值在原数组中的位置不要求连续，重复数字也不增加长度。

| 输入 | 输出 | 说明 |
| --- | --- | --- |
| `[100, 4, 200, 1, 3, 2]` | `4` | 最长序列为 `1, 2, 3, 4` |
| `[0, 3, 7, 2, 5, 8, 4, 6, 0, 1]` | `9` | 最长序列为 `0` 到 `8` |
| `[1, 0, 1, 2]` | `3` | 重复的 `1` 只计一次 |
| `[]` | `0` | 没有可构成序列的元素 |

关键约束：数组长度为 `0` 到 `10^5`，数值在 `[-10^9, 10^9]` 内；题目要求线性时间算法。

## 解题思路

### 排序为什么还不够？

排序后可以扫描相邻数值，跳过重复元素并统计连续长度，但排序通常需要 `O(n log n)` 时间，达不到题目要求。

要跳过排序，需要快速判断“前一个数”和“后一个数”是否存在。这里不需要原下标和出现次数，因此使用哈希集合即可。

### 只从序列起点扩展

把所有元素加入集合 `values`。对于一个数 `num`：

- 如果 `num - 1` 存在，那么 `num` 是某条连续序列的内部元素，跳过。
- 如果 `num - 1` 不存在，那么 `num` 就是某条连续序列的起点，持续检查后继数字直到断开。

例如集合中包含 `1, 2, 3, 4`，只从 `1` 向后扫描；遇到 `2`、`3`、`4` 时不会重新扫描后面的部分。

### 算法步骤

1. 将数组转换成集合，去重并支持快速存在性查询。
2. 遍历集合中的每个数，判断它是否为起点。
3. 从起点开始不断检查 `current + 1`，统计当前序列长度。
4. 更新最大长度；空数组没有循环，直接得到初始值 `0`。

### 为什么能找到最长序列？

集合中的每条连续序列都有唯一的最小元素，该元素的前驱不存在，因此一定会被识别为起点。由起点向后检查会覆盖整条序列，取所有序列长度的最大值即可。

## 示例推演

以 `[100, 4, 200, 1, 3, 2]` 为例。下表仅按数值大小展示判断过程，实际集合遍历顺序不影响结果。

| 当前数 | 前驱是否存在 | 操作 | 扫描出的长度 |
| --- | --- | --- | --- |
| 1 | 否 | 扩展到 `2 → 3 → 4`，`5` 不存在 | 4 |
| 2 | 是 | 跳过 | — |
| 3 | 是 | 跳过 | — |
| 4 | 是 | 跳过 | — |
| 100 | 否 | `101` 不存在 | 1 |
| 200 | 否 | `201` 不存在 | 1 |

最大长度为 `4`。

## 代码实现

### Java

```java
import java.util.HashSet;
import java.util.Set;

class Solution {
    public int longestConsecutive(int[] nums) {
        Set<Integer> values = new HashSet<>();
        for (int num : nums) {
            values.add(num);
        }

        int longest = 0;
        for (int num : values) {
            if (values.contains(num - 1)) {
                continue;
            }

            int current = num;
            int length = 1;
            // 只从起点扩展，每条连续序列只扫描一次。
            while (values.contains(current + 1)) {
                current++;
                length++;
            }
            longest = Math.max(longest, length);
        }

        return longest;
    }
}
```

### Python

```python
from typing import List


class Solution:
    def longestConsecutive(self, nums: List[int]) -> int:
        values = set(nums)
        longest = 0

        for num in values:
            if num - 1 in values:
                continue

            current = num
            length = 1
            # 只从起点扩展，每条连续序列只扫描一次。
            while current + 1 in values:
                current += 1
                length += 1
            longest = max(longest, length)

        return longest
```

## 复杂度分析

设数组长度为 `n`，去重后的元素数量为 `u`，其中 `u <= n`。集合操作按平均 `O(1)` 分析。

- 建立集合需要期望 `O(n)` 时间。
- 外层遍历进行 `u` 次前驱判断。
- 内层循环只从起点启动。所有成功扩展合计不超过 `u` 次，每条序列另有一次失败的后继判断，失败次数也不超过 `u`。

因此，**总时间复杂度为期望 `O(n)`，空间复杂度为 `O(n)`**。不能仅因存在两层循环，就直接判定为 `O(n²)`。

## 易错点与个人复盘

### 原来的疑问：为什么遍历原数组可能变慢？

原笔记曾将原因归为“哈希冲突”。这里需要修正：**重复出现的序列起点会触发重复扩展，才是这个写法可能退化的关键。**

例如 `[1, 1, 1, 2, 3, 4]`：

- 遍历原数组时，三个 `1` 都会通过“前驱不存在”的检查，于是 `1 → 2 → 3 → 4` 被重复扫描三次。
- 遍历去重后的集合时，`1` 只处理一次，这条序列也只扫描一次。

若起点重复 `r` 次，连续段长度为 `L`，重复扩展的成本可达到 `O(rL)`；当两者都与输入规模成正比时，时间可退化为 `O(n²)`。

所以，遍历原数组并非总会得到错误答案，而是无法保证此处的线性时间。没有重复起点时，两种遍历方式都可能正常完成。原笔记中的超长数组不再保留，使用上面的小例子即可解释原因。

### 其他易错点

- **不要从每个数都向后扫描**：即使已经去重，长连续段也会被重复计算，仍可能退化为平方级时间。
- **不要统计重复值的数量**：`[1, 1, 2]` 的最长长度是 `2`。
- **负数同样适用**：`[-2, -1, 0, 2]` 的最长长度是 `3`，无须特殊分支。
- **遍历集合时不修改集合**：当前方法仅查询，不会触发 Java 集合迭代期间修改的问题。
- **Java 的整数边界**：题目数值限制在 `[-10^9, 10^9]`，这里的前驱和后继运算不会溢出。若推广到完整 `int` 范围，需要额外处理边界，避免最大值和最小值被溢出误连。
- **复盘问题**：能否分别说明“只从起点扩展”和“遍历去重后的集合”各自避免了哪一种重复计算？

建议核对的边界输入：`[]`、`[7]`、`[1, 1, 1]`、`[-2, -1, 0, 2]`、`[1, 2, 10, 11, 12]`，以及起点大量重复的长连续段。
