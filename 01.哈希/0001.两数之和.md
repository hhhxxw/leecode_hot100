## 题意与示例

从数组中选择两个不同位置，使对应数值相加等于 `target`，返回这两个位置的下标。题目保证恰好存在一个有效答案，返回顺序不限。

| 输入 | 一组合法输出 | 说明 |
| --- | --- | --- |
| `nums = [2, 7, 11, 15], target = 9` | `[0, 1]` | `2 + 7 = 9` |
| `nums = [3, 2, 4], target = 6` | `[1, 2]` | 下标不要求相邻于数组开头 |
| `nums = [3, 3], target = 6` | `[0, 1]` | 数值可以相同，下标必须不同 |

关键约束：数组长度为 `2` 到 `10^4`，数值与目标值均在 `[-10^9, 10^9]` 内。

## 解题思路

### 从枚举到查找补数

最直观的做法是枚举所有 `i < j`，检查两数之和，需要 `O(n²)` 时间。

固定当前数 `num` 后，另一个数已经确定为 `target - num`。问题变成：**之前是否遇到过这个补数？如果遇到过，它的下标是多少？**

因此使用哈希表 `seen`，保存“已遍历的数值 → 对应下标”。只保存是否存在的集合不够，因为答案需要返回下标。

### 算法步骤

1. 从左到右遍历数组，当前下标为 `i`，当前数值为 `num`。
2. 计算 `complement = target - num`。
3. 如果补数在 `seen` 中，返回 `[seen[complement], i]`。
4. 否则记录 `seen[num] = i`，继续遍历。

### 为什么先查询，再插入？

处理下标 `i` 时，表中只包含下标小于 `i` 的元素，因此找到的两个下标一定不同。

如果先插入，处理 `[3, 3]` 的第一个 `3` 时，就可能把当前元素自己当作补数，返回 `[0, 0]`。

### 为什么不会漏掉答案？

设答案的下标为 `i < j`。遍历到 `j` 之前，`nums[i]` 已经记录在表中；查询 `target - nums[j]` 就能找到它。对于重复数值，保留其中一个已遍历下标即可。

## 示例推演

以 `nums = [3, 2, 4], target = 6` 为例：

| 当前下标 | 当前数 | 补数 | 查询前的 `seen` | 操作 |
| --- | --- | --- | --- | --- |
| 0 | 3 | 3 | `{}` | 未找到，记录 `3 → 0` |
| 1 | 2 | 4 | `{3: 0}` | 未找到，记录 `2 → 1` |
| 2 | 4 | 2 | `{3: 0, 2: 1}` | 找到补数，返回 `[1, 2]` |

## 代码实现

### Java

```java
import java.util.HashMap;
import java.util.Map;

class Solution {
    public int[] twoSum(int[] nums, int target) {
        Map<Integer, Integer> seen = new HashMap<>();

        for (int i = 0; i < nums.length; i++) {
            int complement = target - nums[i];
            // 表中只有之前的元素，避免重复使用当前下标。
            if (seen.containsKey(complement)) {
                return new int[] {seen.get(complement), i};
            }
            seen.put(nums[i], i);
        }

        // 题目保证有解；保留返回值以满足方法签名。
        return new int[0];
    }
}
```

### Python

```python
from typing import List


class Solution:
    def twoSum(self, nums: List[int], target: int) -> List[int]:
        seen = {}

        for i, num in enumerate(nums):
            complement = target - num
            # 表中只有之前的元素，避免重复使用当前下标。
            if complement in seen:
                return [seen[complement], i]
            seen[num] = i

        # 题目保证有解；与 Java 版本保持一致。
        return []
```

## 复杂度分析

设 `n` 为数组长度，哈希表查询和插入按平均 `O(1)` 分析。

- **时间复杂度：期望 `O(n)`**，每个元素最多查询和插入各一次。
- **空间复杂度：`O(n)`**，最坏情况下保存与数组长度成正比的键值对。

## 易错点与个人复盘

- **返回下标，不是数值**：哈希表的值要保存下标。
- **先查后存**：这是保证不重复使用当前元素的关键。
- **下标 `0` 也是合法答案**：Python 不要写成 `if seen.get(complement)`，否则下标 `0` 会被当作假值。使用 `in` 判断键是否存在。
- **不要用排序后的下标代替原下标**：排序会改变位置，若采用排序思路还需额外保存原下标。
- **复盘问题**：能否用 `[3, 3]` 解释更新顺序，用 `[0, 4, 3, 0]` 解释为什么不能用值的真假判断键是否存在？

建议核对的边界输入：重复数值 `[3, 3]`、包含零 `[0, 4, 3, 0]`、负数 `[-3, 4, 3, 90]`。目标值分别取 `6`、`0`、`0`。
